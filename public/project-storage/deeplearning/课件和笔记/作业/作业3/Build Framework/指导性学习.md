# Part01 自动微分（Build Framework）指导性学习

基于 [part01.ipynb](file:///Users/sakiko/Public/deeplearing/课件和笔记/作业3/Build%20Framework/part01.ipynb) 的内容，本节从零实现一个最小可用的自动微分框架：用 `Variable` 承载数据与梯度，用 `Function` 表达算子并建立动态计算图（Define-by-Run），最终实现 `backward()` 自动反向传播，并用单元测试与梯度检验保证正确性。

## 学习目标

- 理解“变量/函数/计算图/梯度”在自动微分系统中的职责分工
- 能手写最小的 `Variable` 与 `Function`，支持 `Square`、`Exp` 等基本算子
- 理解数值微分与反向传播的差异，并能用梯度检验验证反向传播实现
- 能解释 Define-by-Run（动态计算图）的工作机制
- 能将递归式反传改写为循环（栈/队列），并完成易用性与鲁棒性优化

## 核心概念速记

- Variable：一个“箱子”，至少包含
  - `data`：前向传播的值（本节统一用 `np.ndarray`）
  - `grad`：对该变量的梯度（反向传播得到）
  - `creator`：产生该变量的函数（动态计算图的“连接”）
- Function：一个“算子”，至少包含
  - `forward(x) -> y`：前向计算
  - `backward(gy) -> gx`：给定输出梯度 `gy`，返回输入梯度 `gx`
  - `__call__(input)`：封装前向过程，并在运行时把 `Variable` 与 `Function` 连接起来
- 动态计算图（Define-by-Run）：计算发生时才把“谁由谁算出来”的关系记录在 `Variable.creator` 中
- 反向传播：按计算图的反方向，把梯度从输出传回到输入（本节先支持单输入/单输出链式结构）

## 推荐学习路线（对应 notebook 步骤）

### 步骤1：作为“箱子”的变量（Variable）

- 建立直觉：变量是“容器”，不负责计算，只负责持有 `data`（后续还要持有 `grad/creator`）
- 重点检查：`np.ndarray` 的维度概念，尤其是 0 维数组（标量包装）和向量维度的区分

### 步骤2：创建变量的函数（Function）

- 先写一个最简单的 `Function.__call__`：取出 `input.data`，计算，装回 `Variable`
- 再抽象出 `forward()`：让不同函数只实现 `forward`，统一调用逻辑在 `__call__` 内完成

### 步骤3：函数的连续调用（复合函数）

- 实现 `Exp` 并串联 `Square -> Exp -> Square`，形成更长的计算链
- 这里先关注“前向能跑通”，为后面建立计算图做准备

### 步骤4：数值微分（作为对照与验证工具）

- 用中心差分实现 `numerical_diff(f, x)`，对复合函数求导
- 理解数值微分两大问题：
  - 精度丢失（相近数相减导致有效位数减少）
  - 计算成本高（变量多时需要大量函数评估）
- 本节中数值微分的核心用途：用来做梯度检验，验证反向传播实现是否正确

- 计算图视角：变量（圆）与函数（方）一一对应；前向传值，反向传梯度

### 步骤6：手动进行反向传播（实现 backward）

- 给 `Variable` 增加 `grad`
- 给 `Function` 增加 `input` 保存（反传要用到前向输入）
- 为 `Square/Exp` 写出 `backward(gy)` 的公式
- 先手动按链式顺序回传梯度：从 `y.grad=1` 开始，逐个调用每个函数的 `backward`

### 步骤7：反向传播的自动化（动态计算图）

- 给 `Variable` 增加 `creator`，并在 `Function.__call__` 中把输出变量 `output.creator = self`
- 给 `Function` 同时保存 `input` 与 `output`，反向传播时需要 `y.grad`
- 实现 `Variable.backward()`：从当前变量出发沿 `creator` 反向遍历

关键心法：

- 从“函数视角”看变量：变量是输入/输出
- 从“变量视角”看函数：变量由函数创造，函数是变量的 `creator`

### 步骤8：从递归到循环（更稳健的 backward）

- 用栈结构（list）保存待处理函数：`funcs = [self.creator]`
- 循环 pop 出函数、计算输入梯度，再把更前面的 `creator` 推入栈
- 目的：避免递归过深带来的风险，同时更容易扩展为更复杂的图遍历策略

### 步骤9：让函数更易用（API 与边界条件）

- 把 `square(x)` / `exp(x)` 做成 Python 函数，隐藏 `Square()(x)` 这种调用细节
- 如果 `y.grad is None`，默认把输出梯度设为 `np.ones_like(y.data)`
- 限制 `Variable.data` 类型为 `np.ndarray`，避免混入不支持的类型
- 处理 0 维 ndarray 运算后变成标量的问题：引入 `as_array()`，保证输出仍是 `np.ndarray`

### 步骤10：测试（单元测试 + 梯度检验）

- 用 `unittest` 为 `square` 编写前向与反向测试
- 用梯度检验（数值微分 vs 反传结果）自动验证梯度实现正确性
- 了解 `unittest discover`：自动发现并批量运行测试用例

补充视角：

- 自动微分常见两类：前向模式与反向模式；深度学习训练通常偏好反向模式

## 常见坑（对照排查）

- 把 Python 标量/列表直接塞进 `Variable`：本节约束为 `np.ndarray`
- 忘了保存 `Function.input` / `Function.output`：反传时拿不到 `x` 或 `y.grad`
- 没有初始化 `y.grad`：导致 `backward` 中梯度传播从一开始就是 `None`
- 0 维 ndarray 运算后变成标量：导致后续 `np.ones_like`、类型检查等行为不一致
- 用数值微分验证时 `eps` 过大/过小：过大会带来近似误差，过小会放大精度丢失
